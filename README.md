# NEURO_GEO

Генерация датасета электромагнитного каротажа (empymod), обучение прямого суррогата
7 параметров пласта -> 40 сигналов зонда, обучение обратной сети (PINN) и C++-инференс инверсии.

```
dataset/GEO_40sig_7p_dataset_gen.py     генерация датасета (LHS + empymod -> parquet)
train/pipeline_common.py                общие препроцессинг, сплит, скейлеры, экспорт весов
train/forvard_neuro_train_7p_40sig.py   прямая сеть 7->40 (экспорт FWD_* и скейлеров)
train/PINN_train_40sig_7p.py            обратная сеть 40->7 с физической невязкой (экспорт INV_*)
dll/NEURO_40_7.cpp                      инференс инверсии (PGD по входу прямой сети) для Visual Studio
tools/verify_mirror_symmetry.py         проверка симметрии, на которой построена аугментация
docs/                                   разбор исходных версий скриптов и обоснование правок
```

## Модель и данные

Трёхслойная модель: изотропные вмещающие, анизотропный средний пласт.

| параметр | смысл | диапазон |
|---|---|---|
| `Rh_up`, `Rh_pl`, `Rh_dn` | горизонтальные УЭС слоёв, Ом·м | 1 … 1000 (лог-равномерно) |
| `Rv_pl` | вертикальное УЭС пласта | `Rh_pl` × [1 … 5] |
| `D_up`, `D_dn` | расстояния до границ, м | 0.05 … 4 |
| `Alpha` | угол падения, град | 60 … 120 |

40 сигналов = 2 частоты (400 кГц, 2 МГц) × (4 компенсированные ZZ-фазы + 4 разноса × [A_Amp, A_Phase, B_Amp, B_Phase]),
разносы ZX: 0.96 / 1.62 / 2.28 / 3.00 м.

## Ключевое свойство: зеркальная симметрия

Отклик зеркальной модели (`Rh_up<->Rh_dn`, `D_up<->D_dn`, `alpha->180-alpha`) — точное преобразование исходного:
ZZ-каналы не меняются, `|S| -> 1/|S|`, `arg S -> -arg S` (совпадение до 1e-12, `tools/verify_mirror_symmetry.py`).
Поэтому генератор считает физику только для базовой половины точек, а зеркальные строки получает формулой,
и обучение делит train/val по базовой точке, чтобы зеркало не попадало в валидацию к своему близнецу.

Практическое следствие: компенсированные ZZ-каналы принципиально не различают верх и низ —
информацию об ориентации несут только ZX-каналы.

## Запуск

```bash
pip install -r requirements.txt
python dataset/GEO_40sig_7p_dataset_gen.py     # -> dataset_7p_splitZX_40f.parquet
python train/forvard_neuro_train_7p_40sig.py   # -> engine_weights/ (FWD_*, скейлеры)
python train/PINN_train_40sig_7p.py            # -> engine_weights/ (INV_*), требует FWD_* и скейлеры
```

Генерация 5 млн строк — примерно 14 ядро-часов (~20 мс на точку физики, замер на Python 3.12 / empymod 2.6).
Счёт возобновляемый: посчитанные чанки лежат в `temp_chunks/`, повторный запуск их пропускает.

## Каталог артефактов `engine_weights/`

Оба скрипта пишут в один каталог, который целиком передаётся в `InitEngine`:

```
FWD_W1..5.txt, FWD_b1..5.txt      прямая сеть 7->512->1024->512->256->40
INV_W1..5.txt, INV_b1..5.txt      обратная сеть 40->512->1024->512->256->7
scaler_X_mean.txt, scaler_X_scale.txt, scaler_Y_mean.txt, scaler_Y_scale.txt
best_forward_model.pt, PINN_40sig_7p.pt, preprocess_meta.json, val_mae_physical.txt
```

Веса — из лучшей эпохи, транспонированные, формат `[in, out]`. Скейлеры фитятся только на train прямым
скриптом; PINN их загружает и не фитит заново, поэтому прямая сеть, обратная сеть и DLL живут в одной шкале.
Активация — `nn.GELU()` в точном (erf) варианте; в C++ нужен тот же вариант, а не tanh-приближение.

Сплит train/val — по базовой точке (`SPLIT_MODE='group'`), одинаковый в обоих скриптах, зеркальная пара
не разъезжается между train и val.

## Слепая зона и шум в PINN

Границы глубже `DOI_THRESHOLD = 3.8` м заменяются сентинелом `D = 4.0` м (внутри диапазона генератора и
внутри `max_bounds` DLL): контракт — `D >= 3.8` в выходе инверсии означает «граница за пределами зоны
исследования», а не измеренную глубину. Значение пишется в `preprocess_meta.json`.

Шум обучения задаётся в физических единицах — `NOISE_AMP_DB = 0.05` дБ по амплитудам (`sigma_log10 = дБ/20`,
амплитуды хранятся как `log10|S|`) и `NOISE_PHASE_DEG = 0.2` град по фазовым и ZZ-каналам — и переводится в
масштабированное пространство через `scale_Y`. Валидационный шум генерируется один раз с фиксированным seed,
поэтому `val_loss`, early stopping и `ReduceLROnPlateau` сравнивают эпохи на одной и той же реализации шума.

## C++-инференс

`dll/NEURO_40_7.cpp` — drop-in замена исходного файла в проекте Visual Studio (Eigen, toolset v141, x64).
API: `InitEngine(dir, max_steps, lr)`, `RunPGDInversion(signals40, min7, max7, out7)`, плюс диагностические
`IsEngineReady()` и `GetLastErrorText()`. Вызов инверсии до успешного `InitEngine` больше не обращается к
пустым матрицам: выход заполняется `NaN` и функция возвращается. Чтение весов строгое — отсутствующий файл,
нехватка значений, лишние значения и не-finite числа приводят к `InitEngine == false` с текстом ошибки.

Проверено на собранной библиотеке: паритет инверсии с эталоном на numpy до 2e-7, вызов без инициализации
возвращает `NaN` без зависания, обрезанный `FWD_W2.txt` отвергается, каталог `engine_weights/` из двух
train-скриптов загружается как есть.
